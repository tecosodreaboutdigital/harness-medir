4. Metodologia

Fixa, documentada aqui, para repetir igual em toda atualização futura. Ver build/generate_logbook_metrics.py e build/build_logbook.py no repositório.

Palavras. Contadas a partir do HTML publicado de cada commit (git show <hash>:arquivo), removendo marcação, bloco de código e SVG. Soma as partes 1, 2 e o guia compacto, nos idiomas que existiam naquele commit.

Linhas. Contagem de linhas dos scripts de montagem em build/ e dos documentos de governança (README, STANDARDS, STATUS, NEXT-STEPS, TOOLS, inventário de fontes), por commit.

Tokens. Soma real do campo usage de cada mensagem do assistente no transcript .jsonl desta sessão, em ~/.claude/projects/<projeto>/. Cada evento é atribuído ao commit imediatamente seguinte, por ordem cronológica, mesma técnica usada em outro projeto do autor para o mesmo fim.

Viés conhecido

Leitura de cache cresce com o tamanho acumulado da sessão, não com o esforço do marco específico. Para comparar esforço real entre marcos, use a saída (output), não o total bruto. O total bruto aparece porque é o que a fatura cobra, a saída aparece porque é o que ensina.

Uma sessão contínua cobre o projeto inteiro até aqui, então não há reconstrução retroativa a fazer, ao contrário de projetos mais antigos com dezenas de sessões. Cada marco futuro soma a esta mesma série.

4. Methodology

Fixed, documented here, to repeat identically on every future update. See build/generate_logbook_metrics.py and build/build_logbook.py in the repository.

Words. Counted from the published HTML of each commit (git show <hash>:file), stripping markup, code blocks and SVG. Sums parts 1, 2 and the compact guide, in whichever languages existed at that commit.

Lines. Line count of the build scripts under build/ and the governance documents (README, STANDARDS, STATUS, NEXT-STEPS, TOOLS, source inventory), per commit.

Tokens. Real sum of the usage field on every assistant message in this session's .jsonl transcript, under ~/.claude/projects/<project>/. Each event is assigned to the immediately following commit, in chronological order, the same technique used on another of the author's projects for the same purpose.

Known bias

Cache reads grow with the session's accumulated size, not with the specific milestone's effort. To compare real effort between milestones, use output, not the raw total. The raw total shows up because it is what the invoice charges, output shows up because it is what teaches.

One continuous session covers the entire project so far, so there is no retroactive reconstruction to do, unlike older projects with dozens of sessions. Every future milestone adds to this same series.

4. Metodología

Fija, documentada aquí, para repetir igual en cada actualización futura. Ver build/generate_logbook_metrics.py y build/build_logbook.py en el repositorio.

Palabras. Contadas a partir del HTML publicado de cada commit (git show <hash>:archivo), quitando marcado, bloque de código y SVG. Suma las partes 1, 2 y la guía compacta, en los idiomas que existían en ese commit.

Líneas. Conteo de líneas de los scripts de montaje en build/ y de los documentos de gobernanza (README, STANDARDS, STATUS, NEXT-STEPS, TOOLS, inventario de fuentes), por commit.

Tokens. Suma real del campo usage de cada mensaje del asistente en el transcript .jsonl de esta sesión, en ~/.claude/projects/<proyecto>/. Cada evento se asigna al commit inmediatamente siguiente, en orden cronológico, la misma técnica usada en otro proyecto del autor con el mismo fin.

Sesgo conocido

La lectura de caché crece con el tamaño acumulado de la sesión, no con el esfuerzo del hito específico. Para comparar el esfuerzo real entre hitos, usa la salida (output), no el total bruto. El total bruto aparece porque es lo que cobra la factura, la salida aparece porque es lo que enseña.

Una sesión continua cubre el proyecto entero hasta aquí, así que no hay reconstrucción retroactiva que hacer, a diferencia de proyectos más antiguos con decenas de sesiones. Cada hito futuro se suma a esta misma serie.
